PIPELINE INGESTION DOKUMEN RAG (IMPLEMENTASI SAAT INI)
=====================================================

Tujuan
------
Mengubah satu atau beberapa PDF hukum ketenagakerjaan menjadi chunk terstruktur,
membuat dense dan sparse embedding, lalu menyimpannya ke Qdrant. Proses berjalan
di background setelah API upload mengembalikan job_id.

Urutan fungsi orchestration
--------------------------
1. one_validate_and_save_uploaded_files
2. two_schedule_background_processing
3. three_process_document_job
4. four_extract_document_chunks
5. five_save_vectors_to_qdrant
6. six_mark_document_completed
7. seven_finalize_upload_job

Seluruh fungsi tersebut berada di
backend/src/utils/document/upload_pipeline_utils.py.

Catatan perilaku aktual
-----------------------

1. Pemilihan extraction bersifat native-first. OCR hanya dipakai ketika native text
   kurang dari 200 karakter dan bounding box image terbesar menutupi minimal 70%
   halaman. Kegagalan pemeriksaan image atau OCR menghentikan dokumen itu.
2. OCR yang digunakan adalah Tesseract melalui PyMuPDF, bukan PaddleOCR.
3. OCR page diproses paralel, tetapi parsing legal selalu dilakukan berurutan agar
   state BAB/Pasal/Ayat dan metadata halaman tetap deterministik.
4. Implementasi tidak membuat object parent dan child terpisah. Unit penyimpanan
   adalah chunk Pasal/Ayat maksimal 1.000 karakter. Parent context Pasal baru
   dirakit dari chunk terkait pada pipeline query.
5. JSONL adalah artefak lokal hasil parsing. Retrieval membaca point dari Qdrant,
   bukan langsung dari JSONL.
6. SHA-256 file dan lifecycle ingestion disimpan di
   backend/data/document_registry.sqlite3. File identik ditolak walaupun namanya
   berbeda; ingestion berstatus failed dapat dicoba ulang.

Struktur chunk JSONL
--------------------

- filename
- bab
- bab_title
- pasal
- ayat (null bila Pasal tidak memiliki penanda ayat)
- part
- page_start
- page_end
- pages
- text
- chunk_id: {document_id}-pasal{pasal}-{ayat|noayat}-part{part}

Struktur point Qdrant
---------------------

- id point: UUID v5 dari ingestion_id + chunk_id
- payload: seluruh metadata chunk di atas, point_id, ingestion_id, embedding_model
- named vector "dense"
- named vector "sparse" (indices + values)

Progress dan lifecycle
----------------------

- State job dan riwayat event disimpan in-memory oleh backend.
- Event SSE: document_status dan job_status.
- Stage dokumen: upload, parsing, embedding, indexing, completed, atau failed.
- Satu upload dapat berisi beberapa PDF; kegagalan satu PDF tidak menghentikan PDF
  lain dalam job yang sama.
- Workspace upload sementara dihapus setelah dokumen selesai atau gagal, sedangkan
  file JSONL hasil parsing tetap berada di backend/data/chunks.
