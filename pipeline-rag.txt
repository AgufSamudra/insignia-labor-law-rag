PIPELINE INGESTION DOKUMEN RAG
=============================

Tujuan
------
Mengubah PDF hukum ketenagakerjaan menjadi chunk, membuat embedding dense dan
sparse, lalu menyimpannya ke Qdrant.

Orkestrasi utama
----------------
Fungsi pipeline berada di `backend/src/utils/document/upload_pipeline_utils.py`:

1. Validasi dan simpan file.
2. Buat job background dan kembalikan `job_id`.
3. Ekstrak serta bersihkan teks PDF.
4. Parse struktur hukum.
5. Buat chunk dan simpan JSONL.
6. Buat embedding dan upsert ke Qdrant.
7. Tandai status job dan hapus file sementara.

Alur
----
1. Frontend mengirim PDF ke `POST /v1/documents/upload`.
2. Backend memvalidasi ekstensi, menghitung SHA-256, dan mengecek registry SQLite.
   File duplikat yang sedang atau sudah diproses ditolak; file yang gagal dapat
   dicoba ulang.
3. Backend membuat job berstatus `queued` dan memproses setiap PDF di background.
   Progress dapat dipantau melalui SSE:
   `GET /v1/documents/{job_id}/events`.
4. Teks diambil dengan pendekatan native-first:
   - Native text digunakan jika panjangnya minimal 200 karakter.
   - Full-page OCR (PyMuPDF + Tesseract, bahasa Indonesia) digunakan jika native
     text kurang dari 200 karakter dan gambar terbesar menutupi minimal 70% halaman.
5. Hasil disusun berdasarkan halaman, lalu dibersihkan dari whitespace, karakter
   rusak, header/footer berulang, dan hyphen pemisah baris.
6. Teks di-parse menjadi BAB, Bagian, Paragraf, Pasal, dan Ayat. Teks di luar
   Pasal tidak dibuat menjadi chunk; parsing berhenti pada heading PENJELASAN.
7. Setiap Pasal/Ayat dipecah menjadi chunk maksimal 1.000 karakter tanpa overlap.
   Metadata halaman dan struktur hukum ikut disimpan.
8. Chunk disimpan di `backend/data/chunks/*.jsonl`, lalu diproses per batch.
9. Model embedding default `BAAI/bge-m3-multi` membuat vector dense dan sparse.
   Vector di-upsert ke collection Qdrant dengan nama `dense` dan `sparse`.
10. Jika berhasil, dokumen berstatus `completed`; jika gagal, berstatus `failed`.

Metadata chunk
--------------
`filename`, `bab`, `bab_title`, `pasal`, `ayat`, `part`, `page_start`, `page_end`,
`pages`, `text`, dan `chunk_id`.

Point Qdrant memiliki payload metadata chunk, `point_id`, `ingestion_id`, serta
`embedding_model`. ID point dibuat dari `ingestion_id` dan `chunk_id`.

Catatan
-------
- OCR hanya dipakai jika kondisi di atas terpenuhi.
- OCR dapat berjalan paralel, tetapi parsing tetap berurutan.
- Qdrant menyimpan chunk, bukan object parent. Parent context dirakit saat query.
- JSONL adalah artefak parsing; retrieval membaca data dari Qdrant.
- Status job dan riwayat event disimpan in-memory.
- Satu job dapat berisi beberapa PDF. Kegagalan satu file tidak menghentikan file lain.
