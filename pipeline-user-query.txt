PIPELINE USER QUERY RAG
======================

Tujuan
------
Memeriksa cakupan pertanyaan, mengambil bukti yang relevan dari Qdrant, lalu
menghasilkan jawaban Bahasa Indonesia dengan referensi sumber.

Alur
----
1. Frontend mengirim pertanyaan ke `POST /v1/query`.
2. Backend memvalidasi query (1–2.000 karakter setelah trim). Query kosong
   menghasilkan HTTP 422.
3. Early scope filter memeriksa apakah pertanyaan termasuk hukum ketenagakerjaan.
   Filter memakai `GENERATIVE_MODEL` dengan output JSON boolean.
   Jika di luar cakupan, pipeline berhenti dan mengembalikan jawaban penolakan
   dengan `filtered = true` serta `sources` kosong.
4. Query yang lolos dinormalisasi (Unicode, whitespace, dan format Pasal/Ayat),
   lalu di-rewrite dengan aturan tetap:
   - Query yang menyebut Pasal/Ayat ditambah konteks “ketentuan dalam peraturan ketenagakerjaan”.
   - Query lainnya ditambah “menurut peraturan ketenagakerjaan Indonesia”.
5. `BAAI/bge-m3-multi` membuat vector dense dan sparse.
6. Qdrant menjalankan dense search dan sparse search secara paralel. Hasilnya
   digabung dengan Reciprocal Rank Fusion (RRF).
7. Hasil fusion diurutkan oleh `Qwen/Qwen3-Reranker-4B`.
   Default: maksimal 20 kandidat, ambil 7 hasil, dan buang score di bawah 0,05.
8. Untuk setiap Pasal yang relevan, backend mengambil seluruh chunk Pasal tersebut
   dari Qdrant untuk membentuk parent context (maksimal 6.000 karakter).
   Jika gagal, chunk hasil rerank tetap digunakan.
9. LLM membuat jawaban berdasarkan context dokumen saja, dalam Bahasa Indonesia,
   dan menandai klaim dengan citation `[1]`, `[2]`, dan seterusnya.
10. Backend membersihkan marker reasoning/Markdown dan mengembalikan jawaban,
    sources, serta metadata retrieval. Jika citation tidak dibuat, nomor semua
    sumber ditambahkan otomatis.

Jika bukti tidak lolos rerank, backend mengembalikan jawaban “bukti tidak cukup”
tanpa menjalankan generasi LLM.

Format source
-------------
Setiap source berisi `id`, `document`, `page`, `page_end`, `chapter`, `article`,
`paragraph`, `chunk_id`, `text`, dan `rerank_score`.

Metadata retrieval
------------------
Query yang diproses penuh mengembalikan:
`query`, `normalized_query`, `rewritten_query`, `candidate_chunks`,
`reranked_chunks`, `retrieved_chunks`, dan `latency_ms`.

Query di luar cakupan mengembalikan:
`query`, `filtered = true`, `filter_reason = outside_labor_law_scope`, dan
`retrieved_chunks = 0`.
